# src

## Purpose
All application source code. Organized into api, components, layouts, pages, stores, and utilities. The two root-level files `app.tsx` and `access.ts` are loaded automatically by Umi at runtime and form the authentication and permission backbone.

## Key Files

| File | Description |
|------|-------------|
| `app.tsx` | Umi runtime config: bootstrap auth on load, JWT token refresh, Umi `request` interceptors, `onRouteChange` route guard, 30-minute idle timeout |
| `access.ts` | Umi access control: defines `canManageUsers`, `canManageRoles`, `canViewAudit` from role codes; exports `useAccess()` hook and `computeAccess()` helper |

## For AI Agents

### Working In This Directory
- Always use the `@/` alias instead of relative `../../` imports
- `app.tsx` must export a named `request` object (Umi plugin config) and an `onRouteChange` function — changing these affects all API calls and route guards globally
- Never import from `.umi/` or `.umi-production/` — these directories are auto-generated by Umi
- Authentication white-list (no token required): `/login`, `/change-password`, `/403`

### Common Patterns
- Permission checks: `const { canManageUsers } = useAccess()` — Umi picks up `access.ts` automatically
- Global state: import from `@/stores/*`
- API calls in pages use `@/api/*`（经 `client.ts` 直连真实后端）

### Testing Requirements
- No test runner configured yet; add tests adjacent to the file under test (e.g., `stores/__tests__/auth.test.ts`)

## Dependencies

- `utils/token` → used by `app.tsx` and auth-related utilities
